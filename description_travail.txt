DESCRIPTION ET EXPLICATION DU TRAVAIL : GESTION DE RÉCOLTE ET RENDEMENT

1. DESCRIPTION GÉNÉRALE DU PROJET
================================
Le projet "Gestion de Récolte et Rendement" est une application web développée avec Symfony 6, permettant aux agriculteurs de gérer leurs récoltes, calculer les rendements, et archiver les données. L'application utilise une architecture MVC avec des contrôleurs, entités Doctrine, repositories, et templates Twig.

2. TECHNIQUES UTILISÉES AU NIVEAU DU CONTRÔLE DE SAISIE ET CODE
===============================================================

A. CONTRÔLE DE SAISIE
---------------------
- **Validation côté client** : Utilisation d'HTML5 avec attributs comme `required`, `min`, `max` pour la validation de base
- **Validation côté serveur** : Utilisation des contraintes Symfony Validator (Assert) dans les entités
- **Validation personnalisée** : Création de validateurs personnalisés pour les règles métier complexes

B. RÔLE DU REPOSITORY
--------------------
Les repositories Doctrine servent d'intermédiaire entre les contrôleurs et la base de données :
- Encapsulation des requêtes complexes
- Méthodes personnalisées pour la recherche et les statistiques
- Optimisation des requêtes avec des jointures et des critères de filtrage

C. ROLE DE DOCTRINE
-------------------
Doctrine ORM gère la persistance des objets :
- Mapping objet-relationnel automatique
- Gestion des relations entre entités (OneToMany, ManyToOne)
- Migrations pour l'évolution du schéma de base de données
- Query Builder pour les requêtes complexes

D. AUTRES TECHNIQUES UTILISÉES
-------------------------------
- **Stimulus JS** : Pour l'interaction front-end (recherche en temps réel)
- **AJAX** : Pour les requêtes asynchrones sans rechargement de page
- **Twig** : Moteur de templates pour la séparation logique/affichage
- **Bootstrap** : Framework CSS pour l'interface responsive

3. VALIDATION ASSERT
===================
Les contraintes Assert de Symfony permettent de valider les données avant la persistance :

```php
#[Assert\NotNull(message: 'La quantité est obligatoire.')]
#[Assert\Positive(message: 'La quantité doit être strictement supérieure à 0.')]
private float $quantite;

#[Assert\LessThanOrEqual('today', message: 'La date de récolte ne peut pas être dans le futur.')]
private ?\DateTimeInterface $date_recolte;
```

Ces contraintes sont automatiquement vérifiées lors de la soumission des formulaires.

4. VALIDATION SERVEUR
=====================
La validation serveur se fait dans les contrôleurs Symfony :

```php
if ($form->isSubmitted() && $form->isValid()) {
    // Traitement des données validées
    $entityManager->persist($recolte);
    $entityManager->flush();
    return $this->redirectToRoute('app_recolte_index');
}
```

Elle utilise les contraintes Assert définies dans l'entité et peut inclure des validations métier personnalisées.

5. POURQUOI L'ENTITÉ RECOLTE.PHP N'A PAS DE CONTRAINTE ASSERT SUR CERTAINS CHAMPS
==================================================================================
L'entité Recolte utilise des contraintes Assert sur les champs critiques :
- Quantité : NotNull, Positive
- Date : NotNull, LessThanOrEqual (pas de date future)
- Qualité : NotBlank, Choice
- Type culture : NotBlank, Length
- Localisation : NotBlank, Length

Certains champs comme `id_user` n'ont pas de contraintes Assert car ils sont définis automatiquement dans le contrôleur lors de la création, évitant ainsi les erreurs de validation inutiles.

6. DIFFÉRENCE ENTRE LES FICHIERS .ENV ET VENDOR
===============================================
A. Fichier .env
---------------
- Contient les variables d'environnement (configuration locale)
- Non versionné (dans .gitignore)
- Définit : DATABASE_URL, APP_ENV, etc.
- Permet la configuration par environnement (dev, prod, test)

B. Dossier vendor/
-----------------
- Contient les dépendances PHP installées par Composer
- Généré automatiquement par `composer install`
- Contient les bibliothèques tierces (Symfony, Doctrine, etc.)
- Versionné partiellement (composer.lock définit les versions exactes)

7. TRAVAIL SUR LES STATISTIQUES
===============================
Les statistiques sont calculées dans les repositories et contrôleurs :

A. Statistiques des Récoltes
----------------------------
- Répartition par qualité (excellente, bonne, moyenne, mauvaise)
- Quantité totale par période
- Recherche par mois/année

B. Statistiques des Rendements
-----------------------------
- Productivité moyenne par culture
- Répartition par classe de rendement (faible, moyen, bon, élevé)
- Calcul automatique : productivité = quantité / surface

8. TRAVAIL DE RECHERCHE
=======================
La recherche utilise plusieurs techniques :

A. Recherche Simple
-------------------
- Recherche textuelle sur type_culture et localisation
- Utilise LIKE SQL avec paramètres sécurisés

B. Recherche Avancée avec AJAX
-------------------------------
- Recherche en temps réel sans rechargement
- Utilise Stimulus JS pour l'interaction
- Requête AJAX vers le contrôleur avec paramètres GET

C. Tri et Filtrage
------------------
- Tri par date, type, quantité
- Pagination implicite (tous les résultats affichés)
- Filtrage par utilisateur (sécurité)

9. UTILISATION DE LA MÉTHODE AJAX
=================================
AJAX est utilisé pour améliorer l'expérience utilisateur :

A. Recherche en Temps Réel
--------------------------
```javascript
async function doSearch() {
    const res = await fetch(url.toString(), {
        headers: { 'X-Requested-With': 'XMLHttpRequest' }
    });
    results.innerHTML = await res.text();
}
```

B. Avantages
------------
- Pas de rechargement de page
- Mise à jour partielle du DOM
- Performance améliorée
- Expérience utilisateur fluide

C. Implémentation Symfony
-------------------------
- Détection des requêtes AJAX : `$request->isXmlHttpRequest()`
- Retour de templates partiels pour les résultats
- Gestion des erreurs et états de chargement

==============
Ce projet démontre l'utilisation avancée des fonctionnalités Symfony :
- Validation robuste des données
- Architecture repository propre
- Intégration AJAX pour l'interactivité
- Gestion complète du cycle de vie des données (CRUD + archivage)
- Interface utilisateur moderne avec Bootstrap et cartes responsive</content>
